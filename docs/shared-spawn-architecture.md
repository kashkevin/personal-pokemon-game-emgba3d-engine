# Shared visible wild Pokémon (EmeraldTogether Phase 3)

Owner decisions (2026-10-13): **Option A, visible overworld wild Pokémon** in the style of
*Let's Go*; host-authoritative; used whenever the game is connected to an EmeraldTogether
world, even with one player online; fully offline play keeps the game's own encounters; 8
visible shared spawn slots per map instance, 12 in total during a mass outbreak; first valid
claim wins; a caught or defeated Pokémon disappears for everyone and its slot is refilled.

Status: implemented on `claude/emeraldtogether-expansion` (engine) and
`claude/emeraldtogether-expansion-app` (app); tested in the cloud with the real host, real
companions and two native Linux 3D clients (`native_spawn_proof.py`, see Testing). Not yet
tested on Windows hardware or across two PCs.

## 1. What a player sees

While connected, the grass, cave floors and sand of every route that has land encounters
hold up to 8 wild Pokémon drawn with the game's own overworld Pokémon sprites (the follower
graphics, `OW_POKEMON_OBJECT_EVENTS`), in the 3D view like every other object. Every player
on the map sees the same Pokémon (species and form, shiny palette, gender and Unown letter)
on the same tile, facing the same way. They walk one tile at a time inside their habitat and
turn around now and then; a Pokémon next to a player holds still so it can be talked to. A
shiny one appears with the shiny sparkle and sound; a newly spawned one with the grass (or
cave dust) effect. Pressing A in front of one asks the host for it: the first player gets a
normal wild battle with that exact Pokémon, a second player is told "Another TRAINER is
battling this POKéMON right now!". When it is caught or defeated it disappears for everybody
and the host spawns another one later; when the player runs, loses or the battle is
cancelled it stays for everyone.

Offline (no world, or the link to the host is lost) the game's own overworld wild encounters
(`wild_encounter_ow.c`) work exactly as before. Surfing, fishing and Rock Smash stay personal
in both cases (decision of this phase: shared spawns cover land habitat only).

Every engine change is compiled only into the native PC game (`#ifdef PORTABLE`, and
`multiplayer_spawns.c` is excluded from the GBA build in `Makefile`), so the pinned GBA ROM
stays byte-identical (`f214735b…`, checked after every engine change).

## 3. Host model (app: `shared_spawns.py`)

A **map instance** is a map (key `"group.number"`); all players of one world share it.
Each instance has a board of **slots**:

| Field | Meaning |
| --- | --- |
| `spawn_id` | Unique in the world, never reused (persisted counter). |
| `species`, `form` | Chosen at creation (forms are their own species IDs in this engine). |
| `level` | Chosen at creation from the map's own land encounter slots. |
| `personality` | 32-bit host roll; every game derives the same gender, nature, ability and Unown letter from it. |
| `shiny` | Host roll at creation (1/4096, the approved Gen 6 odds); fixed for its whole life. |
| `x`, `y`, `facing`, `move_seq` | Tile (map coordinates without `MAP_OFFSET`), direction, and a counter that changes whenever the host moves or turns it. |
| `kind` | `normal` or `outbreak` (Phase 4). |
| `state`, `claimant` | `open`, `claimed` (by one player) or `removed`. |
| lifetime, grace | Remaining *active* seconds (see Timers). |

Limits: 8 live slots normally, 12 in total while the map has an outbreak. Ending an outbreak
removes nothing; new spawns wait until fewer than 8 remain, so nothing is duplicated.

### Ownership rules

1. Only the host creates, moves, claims, releases and removes slots.
2. `claim(player, id)`: `granted` if open (or already this player's: a reconnect resumes it),
   `busy` if another player holds it, `gone` if it does not exist or was removed. The host
   processes requests one at a time, so of two simultaneous claims exactly one is granted.
3. `result(player, id, outcome)` is accepted only from the claimant. `caught`/`defeated`
   remove the Pokémon for everyone and answer `consumed` exactly once (a repeat is `gone`);
   `ran`/`lost`/`cancelled` release it (`released`).
4. `release(player, id)`: the claimant walked away without a result.
5. A claimed Pokémon never moves, retires or expires while it is claimed.
6. Disconnect: the claimant keeps the Pokémon for a grace period of 600 active seconds, so a
   battle that was running when the link dropped can still report; reconnecting cancels the
   grace. A connected claimant who is plainly not battling it (on another map, or back on the
   overworld for 20 s without a result) releases it automatically.
7. Ownership changes (grants and catches/defeats) are saved to disk at once.

### Timers (Phase 11 rule)

The board's clock is the shared world's **active clock**: seconds during which at least one
player is connected, started and stopped by the server at the exact join/leave moment. Slot
lifetimes, grace periods, outbreak timers and the World Event scheduler therefore pause while
nobody is online. Saved state holds remaining durations only (never absolute clock values), so
everything resumes correctly after a host restart.

## 4. The spawn director (app: `spawn_director.py`)

Once per active second, for every map with at least one player standing on it:

* **Fill**: up to the limit, one new Pokémon every 2.5 s (3 at once for a newly visited empty
  map), on a habitat tile 3 or more tiles from every player and within about one screen
  (±7 × ±5 tiles) of a player, never on another Pokémon.
* **Species**: an exact port of `MPWild_RandomizeSpecies` for land: the 312 Gen 1–6 families
  of `src/data/mp_wild_pool.h`, rarity weights, time of day (from the shared world clock), the
  area type boosts of `GetAreaTypeBoost`, the Phase 2 weather table (the weather reported by the
  map's first player, else the map's default) and the 35 % lower-stage chance.
* **Wander**: each open Pokémon has a 35 % chance per second to step to an adjacent habitat tile
  of the same elevation that holds neither a player nor another Pokémon (else it turns in place),
  and a 15 % chance to just turn. One next to a player holds still.
* **Retire**: an open Pokémon older than 45 s that is more than 18 tiles from every player is
  removed, so the 8 slots follow the players around large maps.
* **Expire**: open Pokémon live 3–6 active minutes, then disappear and are replaced.

Habitat tiles come from `shared_spawn_catalogue.py`, generated from the pinned engine by
`tools/mp/gen_shared_spawns.py`: the tiles on which the game itself starts land encounters
(`TILE_FLAG_HAS_ENCOUNTERS` and not surfable), without collision, not on the transition or
multi-level elevations the overworld spawner refuses, clear of warps, triggers and the map's
own objects, in an area reachable from a warp or map connection. 119 maps, 11 859 tiles. No
spawn can therefore stand in a wall, a building, water or an unreachable pocket.

## 5. Messages

### Host ↔ companion (protocol 3, JSON)

* `world` (per player) gains `"spawns"`: `{"map_group", "map_number", "slots": [...]}` for the
  map that player stands on (or `null` without a pose). Each slot: `spawn_id, species, level,
  personality, shiny, form, kind, x, y, facing, move_seq, mine, busy, fresh, seconds_left`.
  `mine`/`busy` are that player's view of the claim. At most 12 slots.
* Request `spawn_action`: `{action: claim|result|release, spawn_id, result, seq}`; reply
  `{"outcome": granted|busy|gone|consumed|released|not_claimant, "seq"}`, followed by a world
  broadcast.
* `presence` gains the optional `weather` (the overworld weather the game shows).
* `PROTOCOL_VERSION` 3: mixed versions refuse cleanly at hello.

### Companion ↔ native game (EMV1 mailbox, 384 bytes, `include/multiplayer_spawns.h`)

| Offset | Owner | Content |
| --- | --- | --- |
| 0 | game | magic `EMV1`, ABI version 1, byte size 384 |
| 8 | game | local generation (odd while writing) |
| 12 | game | local record (116 bytes): one action `{seq, kind, result, species, spawn_id, map}`, the player's map and weather, and the spawn objects drawn right now `{spawn_id, x, y} × 12` |
| 128 | bridge | inbound generation (odd while writing) |
| 132 | bridge | flags (`enabled`), action ack, map of the slots, count, 12 × 20-byte slots `{spawn_id, personality, species, level, flags(shiny, mine, busy, outbreak, fresh), x, y, facing, move_seq}` |

Native bridge frames (a second native-only extension next to the battle looks): the game
announces `'w'` (version 1, 12 slots, 384 bytes, 20-byte slots) once the world mailbox is up,
publishes its local record as `'g'` every 100 ms (interleaved with poses and world records so
claims are never starved, but never before its `'w'` has left the control queue: the
companion refuses a `'g'` that precedes `'w'`), and accepts `'n'` inbound records only after
`'w'`, validated (count ≤ 12, listed slots have ids, unused slots zero, slots need
`enabled`). The mGBA path never sees these frames; an emulator client simply keeps its own
encounters.

## 6. Game client (engine: `multiplayer_spawns.c`)

* **Active** while connected and the inbound record says `enabled`; then
  `UpdateOverworldWildEncounter` makes no land spawns of its own (and removes generated ones);
  surfing keeps its own.
* **Drawing** (distance-based): only slots of the current map whose tile is in the drawn area
  around the camera become objects (local IDs 224–235), as long as an object slot and a sprite
  reserve of 12 are free; others are drawn when the player comes close. Graphics come from
  `GetGraphicsIdForMon(species, shiny, female)` (Unown letter and gender from the host's
  personality). A changed tile is walked to with the normal walking animation (more than two
  tiles away: placed directly); facing follows the host.
* **Interaction**: the objects run the existing World Event script
  (`EventScript_MultiplayerWorldEvent`); its specials hand spawn objects to this module.
  The claim waits for `mine`/`busy` (5 s timeout), the battle is an ordinary scripted wild
  battle with the host's species, level, personality and shiny flag (random IVs, the
  catcher's own OT), and the result is posted from the field tick, so it survives an
  unanswered action or a lost link and is reported on reconnection.
* **Stale claims**: a Pokémon the host still marks `mine` although no battle uses it is
  released by the game itself.
* While a script or menu runs the Pokémon stay where they are; leaving the overworld or the
  connection removes them.

Two engine fixes came with this: field objects spawned by the multiplayer layer had no script
lookup (the World Event Pokémon and the shared spawns now return the World Event script from
`GetInteractedObjectEventScript`), and the spawn client must keep its objects while a script
locks the field (the World Event object is still removed then; see KNOWN_ISSUES).

## 7. Edge cases

| Case | Behaviour |
| --- | --- |
| Late join / map change | The next world frame lists the new map's slots; objects appear as the camera reaches them. |
| Reconnect | The companion's new session gets the current slots; a claim held across the drop resumes (same player id). |
| Host restart | Slots, ids, remaining lifetimes and claims are restored; every claim gets its grace. |
| Disconnect during a battle | The battle continues; its result waits in the game and is posted after reconnecting; the host holds the claim for 600 active seconds. |
| Two players press A at once | Exactly one `granted`; the other game shows the busy message. |
| Nobody online | No spawning, wandering or aging. |
| Player stands where a spawn would go | Spawns keep 3 tiles from players; wandering never enters a player's tile. |

## 8. Known limitations

* A claimant who stays disconnected for more than 600 active seconds, finishes the battle
  offline, catches the Pokémon and saves can end up with a copy that another player also
  catches after the grace ran out (the host cannot see an offline catch).
* Weather: the host weighs species by the weather the map's first player reports; players
  whose games show different weather (per-save daily weather) still see the same Pokémon.
* Objects are drawn only within the classic object range around the camera (the engine's 16
  object slots are shared with NPCs and other players); a Pokémon far away in the 3D view can
  appear when the player walks closer.
* Surfing, fishing and Rock Smash encounters stay personal.

## 9. Testing

* App unit tests: `test_shared_spawns.py` (board: limits, claims, results, grace, movement,
  persistence, isolation), `test_spawn_director.py` (catalogue, fill, weights incl. weather and
  area boosts, wandering, retiring, stale claims, per-player views), `test_shared_world.py`
  (active clock, restart, spawn persistence), `test_world_server.py` (two TCP clients: same
  Pokémon, a simultaneous claim race, removal after a catch), `test_world_spawns_companion.py`
  (EMV1 codec and the companion path with a fake bridge).
* Engine: `tools/pc_port/tests/test_mp_bridge.c` (capability, record and inbound frames,
  validation, and the record never overtaking its announcement when a running game
  reconnects at a low frame rate), `check-native`, `check-abi`, `check-game-sections`, GBA
  ROM hash.
* End to end: `scripts/multiplayer/native_spawn_proof.py` (app) with a real world server,
  real companions and two native Linux 3D clients on Route 101 (software OpenGL, about 5
  frames a second each), run native-spawns-8, all 28 checks passed: same spawn ids on the
  same tiles in both games as the host, a host move redrawn by both, a shiny drawn by both,
  a real simultaneous A press (xdotool key presses) with exactly one claim granted and the
  other game shown the busy message, the battle won and the Pokémon removed for everybody and
  no longer drawn by either game, both games still drawing the same remaining Pokémon, and a
  companion restart while its game runs: the game reconnected, rejoined the host and both
  games drew the same Pokémon again. Earlier runs (1-7) found harness problems and these
  engine problems, all fixed: a crash when the spawn code ran before the save was loaded; the
  spawn objects were removed while the claim script locked the field; a reconnecting game at
  a low frame rate sent its spawn record before its announcement (app KNOWN_ISSUES M8).
* Not yet: Windows clients on real hardware, two PCs over a network, 3–4 players.
